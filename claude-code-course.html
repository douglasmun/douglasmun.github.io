The Mental Model — Externalization

Claude Code isn't smarter autocomplete. It's a harness that externalizes memory, skills, and protocols so your context stays clean and your team's expertise compounds.

Every feature maps to one of four dimensions:

🧠 Memory

Externalized state over time. CLAUDE.md is semantic memory. /resume is episodic memory. Obsidian via MCP is an external knowledge base.

🛠 Skills

Externalized procedures. Skills turn improvised prompts into repeatable slash commands. Subagents are skills with isolation. Plugins package skills for distribution.

🔗 Protocols

Externalized interaction structure. MCP defines how Claude Code talks to external tools. plugin.json is a formal contract.

🎛 Harness

The coordinator. Plan mode is control. Worktrees are sandboxing. Diff review is oversight. /cost is observability.

Level 1 · Unaware · Module 02
● What is an AI Agent?

What is an AI Agent?

Understand the agent loop — the core concept that makes everything in this course make sense.

GAP FILLED Why this module exists

The previous course assumed you already knew what an "agent" means. Without this foundation, plan mode, subagents, skills, and hooks are just features to memorize. With it, they're logical consequences of a single idea.

Objective

Explain the agent loop and map it to Claude Code's behavior. Distinguish agents from chatbots, autocomplete, and scripts.

A Chatbot Responds. An Agent Acts.

A chatbot takes your message and produces a reply. An agent takes your goal and works toward it — reading, planning, acting, observing the results, and iterating until the goal is met or it needs your input.

The Agent Loop

Every AI agent follows the same cycle, whether it's Claude Code, a self-driving car, or a robotic arm:

👁
Perceive
Read files, errors, context
→
🧠
Reason
Analyze, plan approach
→
⚡
Act
Edit code, run commands
→
🔍
Observe
Check results, run tests
→
🔄
Iterate
Repeat or report back

The loop continues until the goal is met, the agent gets stuck, or you intervene. That last part is critical — you are the oversight layer.

How Claude Code Implements the Loop

👁 Perceive

Claude Code reads your codebase — files, directory structure, git history, diagnostics, error messages, even screenshots you paste. It builds a mental model of what exists before doing anything.

🧠 Reason

It analyzes the problem, considers the codebase conventions (from CLAUDE.md), and formulates an approach. In plan mode, this step is made visible to you — you see the thinking before any action.

⚡ Act

It edits files, creates new ones, runs shell commands, calls external tools via MCP. Each action produces a diff or output that you can review.

🔍 Observe

It checks the results — did the tests pass? Did the build succeed? Did the linter flag anything? If something failed, it loops back to reason about why.

🔄 Iterate or Stop

If the goal isn't met, it tries again. If it needs clarification, it asks you. If it's done, it presents the final result for your approval. Nothing lands without your sign-off.

The Spectrum: From Prompt to Multi-Agent

LevelWhat it doesExample
PromptOne input → one output. No loop.ChatGPT answering a question
ChainSequence of steps, fixed order.LangChain pipeline
AgentGoal-directed loop. Chooses tools, iterates.Claude Code editing your repo
Multi-AgentMultiple agents with specialized roles.Claude Code subagents

Why This Matters for the Rest of the Course

Plan mode exists because of Reason

Plan mode makes the reasoning step explicit and reviewable. You approve the plan before Act begins.

Subagents exist because of scope

A single agent loop has a finite context. Subagents run their own loops in isolation — perceive, reason, act, observe — and return a summary. Your main agent's context stays clean.

Skills exist because of Act

Skills are pre-defined action sequences. Instead of the agent improvising a code review every time, a skill gives it a structured procedure to follow.

Hooks exist because of Observe

Hooks add deterministic observations to the loop — auto-run prettier after every edit, auto-run tests after every write. They make the Observe step reliable, not probabilistic.

You exist because of oversight

The agent loop runs until you approve. Diff review, plan approval, permission modes — these are all mechanisms for human-in-the-loop control at different points in the cycle.

Key insight: Every feature in Claude Code maps to a specific part of the agent loop. Once you internalize the loop, you stop memorizing features and start understanding why they exist.

Checkpoint: You can draw the agent loop (perceive → reason → act → observe → iterate) and explain how plan mode, subagents, skills, and hooks each map to a specific step.

Level 2 · Curious · Module 07
● Plan Mode & Diff Review

Plan Mode & Reviewing Diffs

Think before you type. Review before you accept.

Objective

Use plan mode for multi-file tasks and evaluate AI-generated diffs critically.

Shift+Tab cycles: Default → Accept Edits → Plan. Plan mode makes the agent's Reason step visible — you see the thinking before any Act happens.

How to Review Diffs

Read the intent, not just the lines

Does the plan match what you asked for? Reject before diffs generate if not.

Check what was removed

AI may remove error handling or edge cases it considers unnecessary.

Verify the test story

If code changed but tests didn't, ask before accepting.

Use partial acceptance

Accept some files, reject others. Claude iterates on rejections.

Level 2 · Curious · Module 08
● Prompting Patterns

Prompting Patterns That Work

Agentic prompting is different from chatting. These patterns guide the agent loop reliably.

Objective

Rewrite a vague prompt into a constrained, verifiable one.

1. Context First

Feed the Perceive step. "Read src/api/ and understand the routing, then add a /health endpoint following the same pattern."

2. Constrain the Scope

Limit the Act step. "Only modify files in src/auth/ — don't touch anything else."

3. Request Verification

Strengthen the Observe step. "After the change, run the tests and show me the output."

4. Use @file References

Direct the Perceive step. "Look at @src/config/db.ts and update the connection timeout."

5. Iterate, Don't Restart

Keep the Iterate loop going. "Good, but keep the original error message."

Checkpoint: You can rewrite a vague prompt into a constrained, verifiable one.

● Custom Skills

Custom Skills: Externalize Procedures

If you've typed the same instructions twice, you should have a skill.

Objective

Convert a repeat workflow into a reusable slash command.

🛠 Agent Loop Connection

Skills are pre-defined Act sequences. They structure the agent's action step so it follows a proven procedure instead of improvising every time.

# .claude/skills/pr-review/SKILL.md --- name: pr-review tools: [Read, Grep, Bash] user-invocable: true --- Run git diff main..HEAD, review for: 1. Security issues 2. Missing tests 3. Style violations per CLAUDE.md
Skill Type Comparison

Three types of skills — choose based on whether the user needs to pass input:

TypeTriggerExample

$ARGUMENTSUser passes a target/deploy-check staging — environment is the argument

Level 3 · Fluent · Module 14
● Hooks: Automate Guardrails

Hooks: Automate Guardrails

Deterministic shell commands that fire at lifecycle events. They always run.

Objective

Add a hook that auto-formats code on every edit.

🎛 Agent Loop Connection

Hooks make the Observe step deterministic. Instead of hoping the agent checks formatting, hooks guarantee it. They fire at specific points in the loop — before a tool runs, after a tool runs, on session start.

Lifecycle Events

PreToolUse — before any tool
PostToolUse — after any tool
UserPromptSubmit — on prompt send
SessionStart — session opens
Stop — Claude finishes
PreCompact — before compression

Hook Schema (settings.json)

{ "hooks": { "PostToolUse": [ { "matcher": "Edit|Write", "hooks": [{ "type": "command", "command": ".claude/hooks/format-file.sh" }] } ], "PreToolUse": [ { "matcher": "Bash", "hooks": [{ "type": "command", "command": ".claude/hooks/block-dangerous-bash.sh" }] } ] } }
Security Notes

Never pipe remote scripts into hooks (curl ... | bash). Use least-privilege connector scopes in MCP. In Lab C, only scan networks you own or have written permission to test.

Checkpoint: You've added a hook that runs without you thinking about it.
Level 3 · Fluent · Module 15
● Debugging with Claude Code

Debugging with Claude Code

The #1 daily use case. Five patterns that work.

Objective

Debug a real issue using one of the patterns below.

1. Stack Trace Handoff

Paste the error. "Read the files and explain what went wrong." (Perceive → Reason)

2. Reproduction First

"Write a test that reproduces this bug, then fix it." (Act → Observe → Iterate)

3. Bisect with Explore

"Use the Explore agent to find every place we modify the user session." (Nested Perceive loop)

4. Explain-then-Fix

Ask what the code does before what it should do. Mismatches are bugs.

5. Screenshot Debugging

Paste a screenshot for UI bugs. Claude can process images as Perceive input.

Checkpoint: You've debugged a real issue using one of these patterns.

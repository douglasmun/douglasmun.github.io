Terminal, Git & Node — 20-Minute Setup

Claude Code runs in your terminal and works with Git and Node. This page gets you ready in 20 minutes. If you already use these tools daily, skip ahead — you're ready.

Skip this page if: You can open a terminal, run git --version, run node --version, and know what a working directory is. Jump straight to The Mental Model →
Objective

By the end of this page you will have: a working terminal, Git installed and configured, Node.js 20+ installed, and a test project folder ready. Every step has a verification command — run it before moving on.

Step 1 — Open a Terminal

Mac

Press Cmd+Space, type Terminal, press Enter. Or install iTerm2 for a better experience.

Windows

Install Windows Terminal from the Microsoft Store. Use PowerShell or WSL2 (Ubuntu). Claude Code works best in WSL2 on Windows.

Linux

You already have a terminal. Open it with Ctrl+Alt+T on most distros.

# Verify: your terminal is working echo "hello" # Expected output: hello

Step 2 — Install Git

Git tracks changes to your files. Claude Code uses it constantly — checking diffs, creating branches, reading history.

Mac

Run git --version. If not installed, macOS will prompt you to install Xcode Command Line Tools. Accept it. Takes ~5 minutes.

Windows (WSL2)

sudo apt update && sudo apt install git -y

Linux

sudo apt install git -y (Ubuntu/Debian) or sudo dnf install git -y (Fedora)

# Verify git --version # Expected: git version 2.x.x or higher # Configure your identity (one-time) git config --global user.name "Your Name" git config --global user.email "you@example.com"

The Mental Model — Externalization

Claude Code and Cowork are both harnesses that externalize memory, skills, and protocols around the same agent loop. Code gives the agent a codebase. Cowork gives it your work life. Learn the loop once, apply it everywhere.

This course uses the externalization framework from cognitive science and LLM agent research. Following Norman's theory of cognitive artifacts, external tools don't just enhance capabilities — they change the nature of the tasks the model addresses. Every Claude Code and Cowork feature maps to one of four externalization dimensions:

🧠 Memory — Externalized State

What the agent knows across time. In Code: CLAUDE.md (semantic — rules you write), .claude/memory/ (episodic — things the agent learned), /resume (session recovery). In Cowork: context files (about-me.md, brand-voice.md, working-preferences.md), global instructions. Both compound over time — every week you refine them, the agent gets better at your specific work.

🛠 Skills — Externalized Procedures

How the agent acts. In Code: skills with context:fork and $ARGUMENTS, subagents, bundled skills (/debug, /simplify, /batch). In Cowork: plugins with /productivity:start, /data:explore, and domain-specific slash commands. Both transform improvised output into structured, repeatable composition.

🔗 Protocols — Externalized Interaction

How the agent talks to the outside world. In Code: MCP servers, claude mcp add. In Cowork: connectors (Slack, Drive, Notion, Snowflake — 60+ integrations). Both use the Model Context Protocol under the hood. plugin.json is itself a protocol — a formal contract about what a plugin exposes.

🎛 Harness — The Coordinator

Six design aspects: control (plan mode, permission modes, opusplan), sandboxing (worktrees, container isolation, Cowork's VM), oversight (diff review, plan approval, HITL gates), observability (/cost, /usage, OTEL tracing), governance (plugin scopes, private marketplaces, admin controls), and context management (/compact, context rot mitigation, subagent delegation).

What is Claude Code?

Differentiate Claude Code from chat-based AI and code autocomplete. Understand what "agentic coding" means and why it matters.

Objective

Explain in one sentence what makes Claude Code fundamentally different from autocomplete, chat, and traditional coding tools.

Three Generations of AI Coding Tools

Generation 1: Autocomplete

Predicts the next few tokens based on what you've typed. GitHub Copilot, TabNine. You write code; the tool fills in. You are the driver; the AI is a fast typist.

Generation 2: Chat

You describe what you want in a conversation window. ChatGPT, Claude.ai chat. You copy-paste the output somewhere useful. You are the operator; the AI is your advisor.

Generation 3: Agentic

You describe an outcome. The agent reads your codebase, makes a plan, shows it to you, and executes every step autonomously — editing files, running tests, fixing errors, and committing. You are the director; the AI is the executor. This is Claude Code.

Where Claude Code Runs

Claude Code isn't locked to a single surface. It runs in six places, all using the same agent loop:

Terminal (CLI) — the primary interface. Full power.
VS Code — extension with Cmd+Esc launch. Sees your editor context.
JetBrains — IntelliJ, PyCharm, WebStorm, CLion, Rider.
Desktop App — standalone application.
Web — claude.ai/code in your browser.
iOS — mobile access for monitoring and dispatch.

What Makes It Agentic

It reads before it writes

Claude Code explores your codebase — files, directory structure, git history, dependencies, error messages — before proposing any change. It builds a mental model of what exists.

It plans before it acts

In plan mode, Claude shows you its reasoning and proposed approach before touching any file. You approve the plan, then it executes.

It verifies after it acts

Claude can run tests, check linting, and verify its own changes — then iterate if something fails. The loop continues until the goal is met.

Nothing lands without your approval

Every file edit produces a diff you review. You accept, reject, or modify. Claude commits nothing without sign-off by default.

What is an AI Agent?

The core concept behind everything in this course. Once you internalize the agent loop, you stop memorizing features and start understanding why they exist.

Objective

Explain the agent loop, the spectrum from prompt to multi-agent, and map every Claude Code/Cowork feature to a specific step in the loop.

A Chatbot Responds. An Agent Acts.

A chatbot takes your message and produces a reply. An agent takes your goal and works toward it — reading, planning, acting, observing the results, and iterating until the goal is met or it needs your input. The loop is the fundamental difference.

The Agent Loop

Every AI agent follows the same cycle, whether it's Claude Code editing TypeScript, Cowork building a board deck, or a self-driving car navigating traffic:

How Claude Code Implements Each Step

👁 Perceive

Claude reads your codebase — file contents, directory structure, git history, package dependencies, error messages, diagnostics, even screenshots you paste. It builds a mental model of what exists before doing anything. In Cowork: reads your files, connected tools (Slack, Drive, Notion), and context files.

🧠 Reason

It analyzes the problem, considers codebase conventions (from CLAUDE.md), and formulates an approach. In plan mode, this step is made visible — you see the thinking before any action. In Cowork: the "show me your plan before executing" instruction surfaces this step.

⚡ Act

It edits files, creates new ones, runs shell commands, calls external tools via MCP. Each action produces a diff or output you can review. Skills structure this step — pre-defined action sequences replace improvisation. In Cowork: creates documents, spreadsheets, presentations, pulls data from connectors.

🔍 Observe

It checks results — did tests pass? Did the build succeed? Did the linter flag anything? Hooks make this step deterministic: auto-run prettier after every edit, auto-run tests after every write. In Cowork: safety defaults enforce observation rules ("flag all assumptions").

🔄 Iterate or Stop

If the goal isn't met, it loops back. If it needs clarification, it asks. If done, it presents the result for approval. Subagents run their own nested loops in isolation, returning only a summary — your main context stays clean. Nothing lands without your sign-off.

Why This Matters for the Rest of the Course

Plan mode exists because of Reason

It makes the reasoning step explicit and reviewable. You approve the plan before Act begins. Without understanding the loop, plan mode seems like a UI toggle. With the loop, you see it as the agent making its thinking visible.

Subagents exist because of scope

A single agent loop has finite context. Subagents run their own loops in isolation — perceive, reason, act, observe — and return a summary. Your main loop stays clean. Without the loop, subagents seem like a performance trick. With the loop, you see them as context management.

Skills exist because of Act

Skills are pre-defined action sequences. Instead of the agent improvising a code review every time, a skill gives it a structured procedure. Without the loop, skills seem like macros. With the loop, you see them as reliable Act-step templates.

Hooks exist because of Observe

Hooks add deterministic observations — auto-run prettier, auto-run tests, block dangerous commands. Unlike the LLM's probabilistic behavior, hooks always fire. Without the loop, hooks seem like automation. With the loop, you see them as guaranteed quality gates.

You exist because of oversight

The agent loop runs until you approve. Diff review, plan approval, permission modes — these are all mechanisms for human-in-the-loop control at different points in the cycle. You are the most important part of the loop.

Key insight: Every feature in Claude Code and Cowork maps to a specific part of the agent loop. Once you internalize the loop, you stop memorizing commands and start understanding why they exist. The rest of this course is an elaboration of this single diagram.

Checkpoint: You can draw the agent loop (perceive → reason → act → observe → iterate), place Claude Code features on it (plan mode = Reason, skills = Act, hooks = Observe, subagents = nested loops, you = oversight), and explain the spectrum from prompt to multi-agent.

Cowork's Key Capabilities

File System Access

Claude reads and writes to a folder on your computer. Not uploads and downloads — direct read/write. It can reference last month's report to match formatting, pull data from old spreadsheets, and apply brand guidelines mid-task without you mentioning them.

Dispatch

Text a task from your phone → Cowork runs the full workflow on your desktop → you return to finished files. Requires the desktop app running and computer awake. Your phone becomes a remote trigger for complex desktop workflows.

Scheduled Tasks & Routines

Scheduled Tasks run on a timer while your desktop is open. If your machine is off, the task is skipped but shows in task history and auto-runs when you reopen. Routines (research preview) are cloud-hosted — they run even when your laptop is closed.

Computer Use ★ PREVIEW

Claude can interact directly with your screen — open apps, navigate browsers, run tools. It reaches for connectors first (structured data), falls back to browser (web actions), and only uses screen control as a last resort (when no other path exists).

Projects

Isolated workstreams without context bleeding. Run 5 different projects simultaneously — each with its own files, connectors, and context. The Cowork equivalent of Claude Code's git worktrees.

The Core Shift: Delegate Outcomes, Not Steps

This principle applies to both Code and Cowork. It's the single most important prompting shift for agentic tools:

❌ Step-by-step (chatbot thinking)

"Help me make a content calendar for March." — Vague goal, no definition of done, Claude will guess at everything.

✅ Outcome-based (agent thinking)

"I need a complete 30-day content pipeline. Read every file in this folder. Extract my brand voice patterns and top-performing formats. Generate 30 content ideas ranked by audience value. Write full drafts for the top 5. Build a publishing calendar in Excel with dates, platforms, and repurposing plans. Save everything as finished files." — Clear definition of done, specific deliverables, verifiable.

Cowork Context Files = CLAUDE.md for Your Work Life

The highest-leverage setup step for Cowork — building context files — is the exact same concept as CLAUDE.md. Both are semantic memory that compounds over time:

about-me.md

Who you are, your role, responsibilities, industry context, what success looks like. Include 1–2 examples of output you're proud of. Equivalent to the project description in CLAUDE.md.

brand-voice.md

How you communicate: tone, phrases you use naturally, phrases that sound wrong, and 2–3 actual writing samples. Samples are more useful than abstract descriptions. Equivalent to code style rules in CLAUDE.md.

working-preferences.md

How you want Claude to behave: questions before execution? Short or long outputs? File formats? Naming conventions? What should Claude never do without asking? Equivalent to .claude/settings.json and hooks.

Cowork's Top 3 Starter Plugins

Productivity

Task management, calendars, daily workflows. /productivity:start reviews your priorities and organizes your day. Connects to Slack, Notion, Asana, Linear, Jira, Monday, ClickUp, Microsoft 365.

Data Analysis

Drop a CSV, run /data:explore. Claude reads the full dataset, summarizes every column, flags anomalies, and suggests analyses before you've said what you're looking for. Connects to Snowflake, BigQuery, Databricks, Amplitude.

Role-specific (Sales / Marketing / Legal / Finance)

Install the one matching your function. Each loads domain methodology, structured workflows, and connector integrations. Plus partner plugins from Slack, LSEG, S&P Global, Apollo, Common Room.

Cowork Limitations to Know

No cross-session memory

Every session starts fresh. Context files and global instructions are the workaround — same pattern as CLAUDE.md and /resume. Document important decisions in files Claude can read next time.

Tasks die if you close the app

Cowork runs as an active session inside Claude Desktop. Quit = task stops mid-execution. Sleep mode is fine. Quitting is not. Routines (cloud) solve this for scheduled work.

Usage burns fast

Multi-step agent workflows consume significantly more allocation than chat. Batch related tasks into single sessions. Max plans ($100–$200/month) exist for a reason.

Desktop only (for now)

No mobile Cowork, no browser version. Dispatch lets you trigger from your phone, but execution happens on desktop. Use a cloud-synced folder for file consistency across machines.

Cowork Quick-Start Guide — 15 Minutes to Your First Workflow

If you're primarily a Cowork user (not a developer), here's the fastest path to productive use:

Step 1: Create your workspace (2 min)

Create a dedicated folder: ~/claude-workspace/. This is where Cowork reads and writes. Put existing documents you want Claude to reference here — last month's report, your team template, your brand guidelines PDF.

Step 2: Write your context files (5 min)

Create three files in your workspace folder. These are your CLAUDE.md equivalent — they tell Claude who you are and how to work:

# about-me.md I'm [your name], [your role] at [company]. I work on [what you do]. My stakeholders are [who]. Success looks like [definition]. Here's an example of output I'm proud of: [paste 1-2 paragraphs of your best work] # brand-voice.md Tone: [professional/casual/technical/warm] We say: [phrases you use] We never say: [phrases that sound wrong] Example writing sample: [paste 2-3 paragraphs of real writing] # working-preferences.md - Always ask clarifying questions before starting - Show your plan before executing multi-step tasks - Never send emails without my review - Save all outputs as finished files, not drafts - Use bullet points for internal docs, prose for external
Step 3: Install your first plugin (3 min)

Open Claude Desktop → Cowork tab → Customize → Plugins. Install the plugin matching your role: Productivity, Marketing, Sales, Finance, Legal, or Data Analysis. Each comes pre-configured with domain skills and connectors.

Step 4: Connect your tools (3 min)

In Customize → Connectors, connect the tools you use daily. Start with 2–3: Slack + Google Drive is the most common starting point. Each connector uses OAuth — click, authorize, done. Connectors persist across sessions.

Step 5: Run your first real task (2 min)

Give Claude an outcome-based task that uses your context files and connectors:

"Read the files in my workspace. Using my brand voice, write a weekly update email for my stakeholders summarizing this week's Slack conversations in #product-updates. Save as a draft in my workspace."

Claude reads your context files (knows your brand voice), pulls Slack data (via connector), writes in your style, and saves a file. Review, edit if needed, send.

Step 6: Build your first custom plugin (optional, 5 min)

Once you have a workflow you repeat, automate it with Plugin Create. In the Cowork tab, say: "I want to create a plugin that generates weekly stakeholder updates from Slack. Use my brand voice. Include a /weekly-update slash command." Claude assembles the skills, connectors, and commands into a plugin package. Customize and save.

Key insight: If you build a great CLAUDE.md, you already know how to build great context files for Cowork. If you learn Cowork's context file pattern, you'll write better CLAUDE.md files. The skill transfers because the concept — semantic memory for an agent — is the same.

Your First Prompt: Explore → Ask → Edit

# Step 1: Perceive — let Claude read first "Read the files in src/auth/ and explain the login flow." # Claude explores the directory, reads files, builds context # Step 2: Reason — verify understanding "What's the difference between the JWT and session-based paths?" # Claude analyzes, synthesizes, presents its understanding # Step 3: Act — request a verifiable change "Add input validation to the email field — show me the diff first." # Claude proposes edits as a unified diff, waits for y/n

Why "show me the diff first"? This is your first habit to build. By asking Claude to show the diff before applying, you practice the oversight part of the loop. Accept with y, reject with n, or give feedback to iterate.

Four Everyday Commands

These are the context management primitives you'll use in every session. They map to the 🧠 Memory dimension of the externalization framework:

/clear — Fresh context

Wipe the current conversation context and start a new task in the same session. Use between unrelated tasks to prevent context bleeding. Your CLAUDE.md stays loaded — only the conversation resets.

/compact — Compress context

When a session grows long, /compact summarizes earlier conversation to free context space. Claude re-attaches the most recently invoked skills after compaction (up to 25K tokens combined, starting from the most recent). Use proactively before you hit context limits — don't wait for degradation.

/cost — Check spend

Shows token usage and estimated cost for the current session. A typical session consumes 50K–200K input tokens and 10K–50K output tokens. Haiku session: $0.10–$0.45. Sonnet: $0.25–$1.00. Opus: $0.50–$2.25. Check periodically, especially on complex tasks.

/resume — Session recovery

Reopen a previous session. The picker shows your last 50. Useful when you closed the terminal mid-task, or when you want to continue yesterday's work with the context intact.

/btw <question> — Side questions at zero context cost

Ask a meta-question without polluting the main conversation. /btw what's the convention for error handling in this project? — Claude answers using the parent prompt cache, and the exchange never enters conversation history. This is one of the most token-efficient features and a primary defense against context rot.

/context — Visualize context usage

Displays a colored grid showing exactly where your context budget is going — conversation, CLAUDE.md, tool schemas, memory, skills. Run this when costs spike or quality drops. The fastest cost/quality win is usually finding the single biggest offender (often a stale conversation or an oversized MCP result) rather than micro-optimizing everywhere.

/branch / /rewind — Conversation management

/branch [name] forks the conversation — try an approach without losing the main thread. /rewind reverts to a previous checkpoint. Use when you want to explore two approaches and compare results.

/recap — Session summary

Shows a recap of the current session's context — what was discussed, what decisions were made, what files were changed. Useful when resuming after a break.

Context Rot — Why AI Gets Worse the Longer You Chat

As your conversation grows, older context gets compressed or dropped entirely. Claude's behavior drifts from your original instructions. This is context rot — the agent equivalent of memory loss. It affects both Claude Code and Cowork sessions. Understanding it is essential for reliable results.

How to detect it

Claude starts ignoring rules from CLAUDE.md. It repeats patterns you corrected earlier. It "forgets" architectural decisions from the start of the session. Output quality drops noticeably. These are all signs of context rot.

What Context Rot Looks Like in Practice

This is an annotated transcript from a real 40-turn session. The same instruction is given twice — once at the start, once at turn 38. The outputs are different.

Turn 3 · Session start · context clean
Add error handling to the saveTask function. Use console.error, not console.log — that's the project convention.
Claude · turn 3
I'll add error handling following the console.error convention from CLAUDE.md. [Correct diff — uses console.error, matches style guide.]
Turn 38 · 35 turns of unrelated work later · context compressed
Add error handling to the listTasks function.
Claude · turn 38 — context rot in effect
I'll add error handling to listTasks. [Diff uses console.log — the console.error instruction from turn 3 has been compressed out of context and is no longer visible to the model.]

Claude is not malfunctioning — the instruction from turn 3 is genuinely no longer in its context window. This is context rot: information loss through compression, not a bug.

The same session, with /compact at turn 20

Run /compact at turn 20 before starting a new phase of work. Claude summarizes the conversation history into a dense representation — the console.error rule survives because it was referenced multiple times. Turn 38 now produces the correct diff. Same session, same instruction, completely different outcome.

How to prevent it

Five strategies, in order of effectiveness:

CLAUDE.md — critical rules survive compaction because they're re-loaded from disk, not from conversation history
/compact proactively — run it at natural task boundaries, not after you notice drift
Subagent delegation — subagents start with fresh context; complex sub-tasks never pollute the parent
Session splitting — use /clear between unrelated tasks so early instructions don't crowd later ones
Hooks — deterministic behavior (format on save, block dangerous commands) doesn't depend on context at all

Troubleshooting & Recovery

Things will go wrong. Here's what to do when they do:

Claude loops on the same error

It's stuck in an Act → Observe → Act cycle that isn't converging. Press Esc to interrupt. Give explicit direction: "Stop trying that approach. Instead, try X." If that fails, /clear and restate the goal with more constraints.

Output quality collapses mid-session

This is context rot in action. Claude stops following CLAUDE.md rules, repeats mistakes, or produces generic output. Run /compact immediately. If quality doesn't recover, start a fresh session — use /resume on the old one to check what was accomplished, then open a new session for the remaining work.

A subagent gets stuck or hangs

Check the /agents Running tab. If the agent is looping, Ctrl+F kills all background agents. Re-launch with a more constrained prompt or a lower maxTurns to prevent infinite loops.

Costs spike unexpectedly

Check /cost immediately. Common causes: running Opus on trivial tasks, not compacting long sessions, re-reading the entire codebase repeatedly. Switch to Sonnet or Haiku, compact, and scope your prompts tighter.

A hook breaks the workflow

A PreToolUse hook that exits non-zero blocks every tool call. If you can't fix it in-session, edit .claude/settings.json directly to remove the broken hook, then restart Claude.

Cost Management Strategies

Agentic workflows consume significantly more than chat. Here's how to stay efficient:

Use Haiku subagents for exploration

The Explore agent runs on Haiku by default — ~10x cheaper than Opus. Use context: fork + agent: Explore for any read-only investigation before committing to an Opus task.

Use opusplan for refactoring

Opus plans the approach (deep reasoning), Sonnet executes the edits (fast, cheap). You get Opus-quality architecture decisions at Sonnet-level execution costs.

Compact proactively

Don't wait for context rot — a bloated context means you're paying for redundant tokens on every turn. Compact early, especially before starting a new phase of work within the same session.

Use @file references instead of re-reading

Instead of asking Claude to "read all files in src/", point it at specific files: @src/auth/login.ts. Narrower perception = fewer tokens = lower cost.

Split long sessions

One 2-hour session with 500K context costs more per turn than four 30-minute sessions with 100K context each. Split when you cross task boundaries.

--max-budget-usd N — Hard cost cap

The most effective cost control. Set a dollar limit per session: claude --max-budget-usd 5. The session stops when the cap is reached. Essential for headless/CI runs where there's no human watching spend.

Prefer Grep/Glob over Read for discovery

Full file reads are expensive. When searching for patterns, use Grep and Glob first to narrow down, then Read only the files that matter. This can reduce Perceive-step tokens by 10x on large codebases.

--bare for scripted one-shots

Skips loading plugins, hooks, and skills on startup. Faster and cheaper for simple headless tasks where you don't need the full harness.

Enables 1-hour prompt cache TTL for API-key users. Subscription users get this automatically. Dramatically reduces cost on repeated turns — the system prompt and conversation prefix are cached instead of re-processed. Avoid switching models mid-conversation, which invalidates the cache.

Plan Mode & Reviewing Diffs

Think before you type. Review before you accept. These two skills separate productive Claude Code users from frustrated ones.

Objective

The Three Modes

Shift+Tab cycles through three modes. Each maps to a different part of the agent loop:

Default Mode

Claude reads, reasons, and acts — the full loop. It proposes diffs and waits for your approval. Best for: focused tasks where you trust the scope. Agent loop: Perceive → Reason → Act → you approve.

Accept Edits Mode

Claude applies changes automatically without waiting for diff approval. Best for: low-risk tasks like formatting, renaming, or adding comments where you've already reviewed the plan. Agent loop: full loop with auto-accept. Use with caution — pair with hooks for guardrails.

Plan Mode

Claude reads and reasons but does not act. It explores the codebase, analyzes the problem, and presents a detailed plan — then stops. You review the plan, give feedback, and only then switch to Default mode for execution. Best for: anything touching 3+ files, unfamiliar codebases, architectural changes, or any task where the wrong approach wastes more time than planning. Agent loop: Perceive → Reason → stop.

Auto Mode — Intelligent Autonomous Operation

For experienced users who want faster flow without giving up all safety:

claude --auto or config set autoMode true

Auto mode uses an AI classifier to approve routine, low-risk actions (file reads, grep, listing directories) automatically while still prompting you for high-risk actions (file writes, shell commands, git operations). It's the sweet spot between full manual approval and no approval at all — you get faster flow on safe operations without losing oversight on dangerous ones.

When to use auto mode: Daily development on projects you know well, where you trust the codebase and have hooks configured as guardrails. Pair with a PostToolUse hook that runs tests after edits — auto mode handles the routine approvals, hooks catch the mistakes.

When NOT to use auto mode: Unfamiliar codebases, production-critical changes, anything involving secrets or credentials, or when working without hooks configured. In these cases, Default or Plan mode gives you the oversight you need.

When to Use Plan Mode

Multi-file changes (refactors, migrations, renames)
Unfamiliar codebases (the plan reveals Claude's understanding)
Architectural decisions (you want to review the approach, not just the code)
High-risk changes (auth, payments, data access)
When you'd normally sketch on a whiteboard first

How to Review Diffs

Use /diff for an interactive diff viewer — shows both uncommitted changes and per-turn changes so you can see exactly what Claude modified at each step. This is your most important quality gate:

1. Read the intent, not just the lines

Before looking at code changes, check: does the plan match what you asked for? If the approach is wrong, reject the plan before diffs are generated. Don't waste time reviewing code built on a flawed premise.

2. Check what was removed

Deletions are where bugs hide. AI may remove error handling, logging, edge-case branches, or fallback paths it considers "unnecessary." Always scan deletions carefully — they're easier to miss than additions.

3. Verify the test story

If Claude edited business logic but didn't touch tests, ask: "Did this change break any tests? Are there tests that should be updated?" Better yet, add a hook (Module 15) that auto-runs tests after every edit.

4. Check for hallucinated APIs

Claude may call functions, methods, or library features that don't exist in your project. Cross-reference any unfamiliar API calls. This is especially common with newer libraries or internal utilities.

5. Use partial acceptance

You can accept some files and reject others. Claude will iterate on the rejected portions while keeping the accepted changes. This is much faster than rejecting everything and rephrasing.

Prompting Patterns That Work

Universal patterns for any agent — Code or Cowork. These aren't chatbot tricks; they're ways of guiding the agent loop reliably.

Objective

Rewrite a vague prompt into a constrained, verifiable, outcome-based delegation. Use XML tags for complex tasks. Know the common anti-patterns.

Pattern 1: Delegate Outcomes, Not Steps

This is the single most important shift for agentic tools. Stop telling the agent how to work. Describe what done looks like. ChatGPT trained you to write detailed step-by-step prompts. Agentic tools train you to give clear outcomes. One skill depreciates as models improve; the other compounds.

❌ Step-by-step (chatbot thinking)

"First, read the auth module. Then find the login function. Then check if there's validation. Then add email validation using regex. Then add a test."

✅ Outcome-based (agent thinking)

"Refactor the auth module to use Zod for all input validation. All existing tests must pass. Follow the patterns in @src/validation/schemas.ts. Add tests for edge cases (empty string, malformed email, SQL injection attempt). Run tests before committing."

The second version tells Claude what done looks like (Zod validation, passing tests, edge cases covered) without dictating the steps. Claude chooses the best path through the agent loop.

Pattern 2: Context First

Feed the Perceive step before triggering Act. The more Claude understands before acting, the better its first attempt.

# Good: perceive first, then act "Read src/api/ and understand the routing pattern, then add a new /health endpoint following the same pattern." # Bad: act without context "Add a /health endpoint." # Claude guesses at your routing patterns

Pattern 3: Constrain the Scope

Limit the agent's Act surface. Unbounded prompts produce sprawling, hard-to-review changes that trigger context rot.

"Only modify files in src/auth/ — don't touch anything else." "Fix the bug but don't refactor surrounding code." "Add the feature without changing the database schema."

Pattern 4: Use XML Tags for Complex Delegations

Claude is specifically trained to recognize XML tags as structural markers. For multi-component tasks, tags prevent Claude from mixing up what's background context, what's the actual task, and what the guardrails are.

<context> Series B SaaS startup, $8M ARR. Board meeting next Tuesday. Three non-technical board members. </context> <instructions> Build a board deck with financial summary, product update, and hiring pipeline. Save as .pptx with our brand template. </instructions> <constraints> - Professional but not stiff tone - No jargon the non-technical board members won't know - Every slide needs a "so what" — not just metrics - Maximum 15 slides </constraints>

Tag names are flexible — <background>, <rules>, <data>, <output_format>, whatever makes sense for your task. Consistency within a project matters more than naming convention. This works equally well in Claude Code prompts, CLAUDE.md files, skills, and Cowork instructions.

Pattern 5: Front-Load Clarification, Not Correction

Spend 30 seconds aligning before the agent works. Don't spend 10 minutes correcting after.

"DO NOT start working yet. First, ask me clarifying questions so we can define the approach together. Only begin once we've aligned."

Add this to the end of any non-trivial prompt. Claude will ask specific questions about scope, approach, and constraints before executing. In Cowork, this triggers the AskUserQuestion feature — structured forms with options instead of confident guessing.

Pattern 6: Request Verification

Strengthen the Observe step — don't leave it to chance.

"After making the change, run the tests and show me the output." "Verify that the build succeeds before suggesting a commit." "Check if this change breaks any existing imports."

Pattern 7: Batch Related Tasks

Instead of three separate sessions, batch into one. Less usage, better context coherence, more efficient agent loops.

# Claude Code: one session, three related tasks "Read all files in src/api/. Fix lint errors. Add missing JSDoc comments. Run tests. Commit with a descriptive message." # Cowork equivalent: one session, three related tasks "I have receipts in /receipts. Organize by month into subfolders. Create an expense spreadsheet with category totals and formulas. Write a one-page summary for my accountant. Save everything in /outputs."

Pattern 8: Iterate, Don't Restart

If the first attempt is 80% right, say what's wrong rather than rephrasing from scratch. Restarting wastes all the context the agent built. Iteration preserves it.

"Good, but keep the original error message — don't change that string." "The logic is right but use early returns instead of nested ifs." "This is close — also handle the null case on line 47."

Pattern 9: Visual Input — Paste Images Directly

Claude Code can process images pasted directly into the terminal. This is a general Perceive capability, not just for debugging:

Screenshots of UI bugs

"This button is overflowing. Fix the CSS." Paste the screenshot — Claude sees the visual problem and the code simultaneously.

Architecture diagrams

Paste a whiteboard photo or Mermaid diagram screenshot. "Implement this architecture. Start with the data flow layer."

Error screenshots

Paste a browser console screenshot, a terminal error, or a Sentry alert. Faster than copying text — and Claude sees formatting, colors, and context you'd lose in a paste.

Design mockups

Paste a Figma export or hand-drawn wireframe. "Build this component in React. Match the spacing and colors exactly."

Common Anti-Patterns

Too vague

"Make the code better." — Claude doesn't know what "better" means to you. Be specific: "Reduce cyclomatic complexity of processOrder() by extracting validation into a separate function."

Too prescriptive

"On line 47, change x to userCount, then on line 48..." — You're doing Claude's job. Describe the goal: "Rename variables in processOrder() to be descriptive." Let the agent figure out how.

No verification

"Refactor this module." without "Run tests after." — You're trusting the Act step without an Observe step. Always request verification for non-trivial changes.

Restarting instead of iterating

Rephrasing the entire prompt when the first attempt was 80% right. You just threw away all the context Claude built. Say what's wrong with the 20%, not the 100%.

Custom Skills, $ARGUMENTS, & context:fork

Externalize procedures into reusable slash commands. Make them dynamic with parameters. Run them in isolated subagents for clean context.

Objective

🛠 Externalization: Procedural Knowledge

Skills transform improvised prompts into structured, repeatable procedures. The YAML frontmatter is the specification (what, when, permissions); the body is the execution (how). This maps to the Act step in the agent loop — structured action instead of improvisation.

What skills are — and are not. A skill is a persistent prompt, not a script. When you invoke /pr-review, Claude reads the SKILL.md body as its instructions and then reasons and acts — just as if you had typed those instructions directly. There is no compiled code, no deterministic execution path, no guaranteed output format. The skill makes Claude more consistent and more repeatable, but it is still Claude reasoning from natural language each time.

This means: skills can't loop, can't branch conditionally, can't call external APIs, and can't guarantee identical output on identical input. What they can do is encode your team's best practices, constraint set, and process into a reusable form that Claude follows reliably. Think of a skill as a standing operating procedure, not a function call.

Skill Anatomy

Skills live in .claude/skills/ (team, committed to repo) or ~/.claude/skills/ (personal). Each is a folder with a SKILL.md file and optional helper scripts. Slash commands and skills are unified — .claude/commands/ still works but .claude/skills/ is recommended.

Use $ARGUMENTS to accept parameters from the slash command. /deploy-check staging passes "staging" as the argument:

Pattern 3: Forked Skill (auto-subagent)

Add context: fork and agent: to frontmatter. The skill runs in an isolated subagent — your main context stays clean. Results are summarized back. This is the most powerful pattern for exploration and research tasks.

context: fork vs agent: — what each field does. They are independent.

Built-in Subagents

Nested agent loops that protect your main context. Up to 10 in parallel. Background them and keep working.

Objective

🎛 Agent Loop Connection

Subagents are nested agent loops. Each runs its own perceive → reason → act → observe cycle in isolated context, then returns a summary to the parent loop. This is the primary defense against context rot — complex sub-tasks get fresh context instead of polluting your main session.

Three Built-in Agents

Explore — Perceive only

Read-only, runs on Haiku (fast, cheap). Maps your codebase, finds references, traces call chains, answers structural questions. Cannot edit files. Best for: "Where is X used?", "How does Y work?", codebase mapping before a refactor. Use via skills with context: fork + agent: Explore, or ask Claude to "use the Explore agent."

Plan — Perceive + Reason

Gathers context deeply, synthesizes, and returns a recommended approach. Analytical, not executable. Best for: designing a multi-file change, evaluating tradeoffs, creating a migration plan. Claude uses this automatically in plan mode.

General-purpose — Full loop

Has all tools — read, edit, run commands, write files. Runs a complete agent loop in isolation and reports back. Best for: independent sub-tasks ("add tests for module X while I work on module Y"), documentation generation, multi-perspective analysis.

Working with Subagents

/agents — The dashboard

Open with /agents. Two tabs: Library (available agents — built-in + custom) and Running (active agent tasks with status). Monitor parallel work without leaving your main session.

Ctrl+B — Background a running agent

If a subagent is running and you want to keep typing, Ctrl+B sends it to the background. It continues working and reports back when done. Queue your next task immediately — don't wait for the agent to finish.

Parallel execution

Up to 10 subagents can run simultaneously. Ask Claude to "launch three agents in parallel" for tasks like: compare implementations across frameworks, analyze multiple files for the same pattern, or run different test strategies simultaneously.

When to Delegate vs. Do It Yourself

Delegate when...

The task is independent (doesn't need your main conversation's context), exploratory (you're not sure what you'll find), or would pollute your main context with irrelevant detail.

Don't delegate when...

The task depends on earlier conversation context, requires your real-time judgment at each step, or is a quick question the main session can answer faster than spinning up a subagent.

The Lab: Threat Hunting Agent Squad

Build a 4-agent pipeline where each agent has a distinct role, distinct tools, and defined communication boundaries. The pipeline accepts raw threat intelligence and produces a structured, actionable report.

Phase 1: Agent Design (~2 hrs)

Define roles, responsibilities, and tool permissions for each agent. Specify what each agent can and cannot do. Document the data flow between agents — what format does Agent 1's output need to be in for Agent 2 to consume it?

Agent 1: Collector

Ingests raw CTI notes, threat reports, blog posts, or log snippets. Handles document parsing, encoding normalization, and format detection. Outputs a clean, structured JSON document. Tools: file reader, URL fetcher, encoding detector. Maps to: Claude Code's Explore agent (Perceive-only).

Agent 2: Extractor

Extracts structured data: IOCs (hashes, IPs, domains, URLs), TTPs (techniques and procedures), threat actor names, malware families, and targeted sectors. Uses regex for IOCs and LLM reasoning for TTPs. Tools: regex engine, NER model, LLM extraction chain. Maps to: specialized Reason step.

Agent 3: Mapper

Maps extracted TTPs to the MITRE ATT&CK framework. Assigns technique IDs (e.g., T1059.001), tactics, and confidence scores. Cross-references against the ATT&CK knowledge base. Tools: ATT&CK API or local JSON, similarity search. Maps to: Plan agent (Perceive + Reason).

Hooks & Safety Defaults

Deterministic shell commands that fire at lifecycle events. They always run — unlike LLM behavior, which is probabilistic. Hooks are your quality gates.

Objective

🎛 Agent Loop Connection

Hooks make the Observe step deterministic. Instead of hoping the agent checks formatting or runs tests, hooks guarantee it. They fire at specific points in the agent loop — before a tool runs (PreToolUse), after a tool runs (PostToolUse), when a session starts, when context compacts. This is the harness's enforcement layer.

The /hooks Interactive UI — Step by Step

Run /hooks for a menu interface. It writes .claude/settings.json for you — no manual JSON editing required. Here's exactly what the flow looks like for adding the two hooks you need for the checkpoint:

Hook 1: Auto-format on edit (PostToolUse)
  1. Run /hooks → select PostToolUse
  2. Matcher: type Edit|Write (matches either tool)
  3. Hook type: command
  4. Command: npx prettier --write $CLAUDE_FILE_PATH || true
  5. Save → Claude writes the entry to .claude/settings.json

Verify: make any edit → you should see prettier run automatically in the output.

Hook 2: Block destructive Bash (PreToolUse)
  1. Run /hooks → select PreToolUse
  2. Matcher: Bash
  3. Hook type: command
  4. Command: echo "$CLAUDE_TOOL_INPUT" | grep -qE "rm -rf|DROP TABLE|sudo rm" && exit 2 || exit 0
  5. Save

Exit code 2 = block + show error to Claude. Exit code 1 = block silently. Exit code 0 = allow. Verify: ask Claude to run rm -rf /tmp/test — it should be blocked.

Five Hook Types

The course so far has shown command hooks. There are four more types:

command

Run a shell command. The most common type. Output is returned to Claude.

http

POST the event JSON to a URL. Use for external logging, Slack notifications, or webhook-based workflows.

Call a tool on a connected MCP server. Use when you want a hook to trigger an action in an external system (create a Jira ticket, send a Slack message).

prompt

Evaluate the event with the LLM. Use for smart guardrails: "Is this bash command potentially destructive?" — the LLM classifies and the hook blocks based on the answer.

agent

Run an agentic verifier — a full agent loop that checks the proposed action. The most powerful type. Use for complex validation (e.g., "does this code change break the API contract?").

The bundled /debug skill provides a structured debugging workflow out of the box. Five Manual Debugging Patterns

1. Stack Trace Handoff

Paste the full error and stack trace. Ask Claude to trace the execution path and identify root cause. "Here's the stack trace from production. Read the relevant source files and explain what went wrong." This maps to Perceive → Reason — give Claude maximum signal before asking for analysis.

2. Reproduction First

Ask Claude to write a minimal reproduction before fixing. "Write a test that reproduces this bug, then fix it so the test passes." This maps to Act → Observe → Iterate — the test is the verification mechanism built into the fix itself.

3. Bisect with Explore

Delegate to the Explore subagent to narrow down where the bug lives before committing main context. "Use the Explore agent to find every place we modify the user session object." This is a nested Perceive loop — the subagent maps the territory, returns a summary, and your main session stays clean.

4. Explain-then-Fix

Ask Claude to explain what the code does before asking what it should do. Mismatches between the two are the bug. "Explain what processOrder() does step by step. Then tell me what it should do based on the JSDoc comment."

5. Screenshot Debugging

For UI bugs, paste a screenshot directly into the terminal. Claude can process images as Perceive input. "This button should be aligned right, but it's overflowing. Here's a screenshot. Fix the CSS."

When to Delegate Debugging to a Subagent

Delegate when...

The bug might be in one of many files (use Explore to narrow down), the investigation is exploratory (you don't know where to look), or the debugging would pollute your main context with irrelevant code.

Don't delegate when...

You already know which file has the bug, the fix is straightforward, or you need to maintain conversational context about the broader task the bug interrupted.

End-to-End Worked Example: Bug Report to Commit

This walkthrough ties together plan mode, subagents, hooks, skills, and diff review — everything from Levels 2–3 — into a single realistic workflow. Follow along in your own project.

The bug report

"POST /api/orders returns 500 when the cart contains a product with a price of $0.00. Stack trace points to calculateTotal() in src/orders/pricing.ts."

Step 1: Enter plan mode — Perceive + Reason

Press Shift+Tab to enter plan mode. Paste the bug report. Claude reads the stack trace, explores src/orders/pricing.ts and its callers, and proposes an approach — without editing anything yet.

"Here's a bug report: POST /api/orders returns 500 when the cart has a $0.00 product. Stack trace points to calculateTotal() in src/orders/pricing.ts. Research the issue and propose a fix plan."

Claude's plan: "The issue is a division-by-zero in the discount calculation when basePrice is 0. I'll add a guard clause, update the existing test, and add a new edge-case test."

Step 2: Delegate exploration — Subagent

Before approving, verify the scope. Use the Explore agent to check if the same pattern exists elsewhere.

"Use the Explore agent to find every place we divide by price or amount in src/orders/. Are there other division-by-zero risks?"

Explore returns: "Found 3 division operations in pricing.ts, 1 in discount.ts. The discount.ts one has the same vulnerability." You now know the fix needs to cover two files, not one. The plan mode approach caught this before any code was written.

Step 3: Approve and execute — Act

Switch back to default mode (Shift+Tab). Approve the plan with the expanded scope.

"Good plan, but also fix the same issue in discount.ts. Add guard clauses to both. Write a failing test first, then fix it so the test passes."

Claude writes the failing test (Reproduction First pattern), adds guard clauses to both files, and runs the test suite.

Step 4: Hooks fire automatically — Observe

Your PostToolUse hook auto-runs prettier on every edited file. Your test hook auto-runs pnpm test after writes. You don't think about formatting or testing — the hooks handle the Observe step deterministically.

Hook output: "✓ prettier: 2 files formatted. ✓ tests: 47 passed, 0 failed."

Step 5: Review the diff — Human oversight

Run /diff. Check: are the guard clauses correct? Did Claude remove any existing logic? Are the new tests meaningful (not just asserting the function exists)? Accept the changes you're happy with.

"Looks good. Commit with message: 'fix: guard against zero-price division in pricing and discount modules'"
Step 6: Commit — Done

Total time: ~4 minutes. Without Claude Code: reproduce manually, find both files, write fix, write tests, run formatter, run tests, write commit message — probably 30–45 minutes. The agent loop compressed 6 steps into a supervised flow where you made decisions and Claude did the work.

What this example demonstrates: Plan mode (visible Reason before Act), Explore subagent (nested Perceive to widen scope), Reproduction First debugging pattern (failing test before fix), hooks (deterministic Observe — formatting + tests), /diff (human oversight before commit), and outcome-based prompting (describe what done looks like). These are Levels 2–3 features working together as a system, not isolated commands.

Build the core safety layer: an allowed/denied command system that sits between the LLM's tool calls and actual execution. The LLM proposes commands; your enforcement layer validates them before execution.

# Command enforcement skeleton ALLOWED_CMDS = ["nmap -sn", "dig", "whois", "ping -c 4", "traceroute"] DENIED_CMDS = ["rm -rf", "curl | bash", "sudo", "chmod 777", "wget -O-|sh"] def validate_command(cmd: str) -> tuple[bool, str]: # Check denied patterns first (blocklist) for denied in DENIED_CMDS: if denied in cmd: return False, f"[BLOCKED] '{denied}' is not permitted" # Check allowed patterns (allowlist) if not any(cmd.startswith(a) for a in ALLOWED_CMDS): return False, "[BLOCKED] Command not in allowed list" return True, "OK" def execute_safe(cmd: str, timeout: int = 30) -> str: is_ok, reason = validate_command(cmd) if not is_ok: log_event("DENIED", cmd, reason) return reason # Run inside Docker with resource limits result = docker_exec(cmd, timeout=timeout, mem_limit="256m") log_event("EXECUTED", cmd, result) return result

All commands execute inside a Docker container with: read-only filesystem (except /tmp), no network access by default (enable per-command), CPU and memory limits, non-root user, and automatic cleanup after timeout. Claude Code: /loop and /schedule

/loop runs a prompt on a schedule inside your current session. /schedule creates persistent routines that survive session restarts:

# In-session recurring task /loop every 1h "check the latest 5 open PRs, leave a review comment on any with missing tests" # Persistent routine (survives restarts) ★ PREVIEW /schedule "Run security scan on main branch every morning at 9am" # Push-to-talk voice input (hold spacebar) /voice # Kill all background agents Ctrl+F

When to Use Which

/loop — ephemeral, in-session

Lives only as long as your terminal is open. Best for: monitoring during active work sessions (watch CI while you code), periodic checks during a long refactor (re-run tests every 30 min), development-time automation (check for new issues while coding). Stops when you close the session.

/schedule — persistent, cross-session ★ PREVIEW

Survives restarts. Best for: daily standup preparation (generate a summary every morning), periodic security scans, weekly report generation. Runs at the scheduled time if Claude Code is available.

Neither — use CI instead

If the task should run whether or not you're at your computer, on every PR, or on every commit — that's a CI job, not a /loop or /schedule. Use claude -p in a GitHub Action (Module 20).

Real-World Scheduling Patterns

# Monitor CI while coding /loop every 5m "check CI status for current branch, alert if failed" # Watch for dependency vulnerabilities /loop every 2h "run npm audit, report any high/critical findings" # Auto-generate end-of-day summary /schedule "At 5pm, summarize today's git commits into a standup note" # Self-pacing: /loop adjusts intervals based on results /loop "check for new GitHub issues assigned to me" # Claude picks the interval

Voice Input

/voice — Push-to-talk

Hold spacebar to dictate. 20 languages supported. Great for complex requirements where typing is slow, pair-programming sessions where your hands are on the keyboard, and accessibility. Particularly powerful for dictating architectural descriptions or debugging narrations.

Managing Background Work

Ctrl+B — Send to background

Background a running task so you can keep typing. The agent continues working and reports back when done.

Ctrl+F — Kill all background agents

Emergency stop for all background and scheduled tasks. Use when a /loop is misbehaving or an agent is stuck.

Cowork scheduling is more advanced:
• Scheduled Tasks — run on a timer while your desktop is open. If your machine is off during a scheduled run, the task is skipped but shows in task history and auto-runs when you reopen the app.
• Routines ★ PREVIEW — cloud-hosted automation that runs even when your laptop is closed. The agent equivalent of cron — your machine doesn't need to be on.
• Dispatch — text a task from your phone → Cowork runs the full workflow on your desktop → you return to finished files. Requires desktop app running and computer awake. Your phone becomes a remote trigger.

Git Worktrees & /batch

Objective

🎛 Externalization: Sandboxing

Worktrees are the harness's sandboxing layer. Each Claude session operates in an isolated directory with its own branch. No stashing, no conflicts, no context contamination between parallel work streams.

Parallel Worktree Sessions

# Terminal 1: auth feature claude -w feature-auth "Implement OAuth2 PKCE flow for the login endpoint" # Terminal 2: billing feature claude -w feature-billing "Add Stripe subscription management to the billing module" # Terminal 3: bugfix claude -w bugfix-cors "Fix the CORS headers for the API gateway"

All three sessions work simultaneously. Skills, agents, and CLAUDE.md are discovered correctly from worktrees. Each branch gets its own git history. Merge when ready.

When to Use Worktrees vs. Subagents vs. Sessions

Use worktrees when...

Tasks are independent features on separate branches. You need full git isolation. You want to merge each piece separately. The work is substantial (hours, not minutes). Example: two features + a bugfix in parallel.

Use subagents when...

Tasks share the same branch but can run in parallel. You need results synthesized into your main session. The work is exploratory or analytical (minutes, not hours). Example: analyze 5 modules for the same pattern.

Use separate sessions when...

Tasks are in different projects entirely. No shared codebase. Example: fix a bug in project A while starting a feature in project B.

Glossary

Agent Loop
Perceive → Reason → Act → Observe → Iterate. The fundamental cycle that all AI agents follow. Every Claude Code and Cowork feature maps to a step in this loop.
Externalization
The framework for this course. Externalizing memory, skills, and protocols into a harness so the agent (and your team) can access them reliably. From Norman's cognitive artifacts theory.
Harness
The coordination layer around the agent: plan mode, hooks, permission modes, observability, sandboxing. The harness controls how the agent acts — deterministically, not probabilistically.
Context Rot
Quality degradation as conversations grow. Older context gets compressed or dropped, causing Claude to drift from instructions. Prevented by /compact, /btw, subagent delegation, and CLAUDE.md.
CLAUDE.md
Project-level semantic memory. Loaded every session, survives compaction. Contains stack, commands, conventions, and don'ts. The most important file for Claude Code.
context:fork
Skill frontmatter that runs the skill in an isolated subagent. Your main context stays clean. Results are summarized back. Used for exploration and research tasks.
$ARGUMENTS
Variable in skill body that captures parameters from the slash command. /deploy staging passes "staging" as $ARGUMENTS.
MCP
Model Context Protocol. Open standard for connecting AI agents to external tools. Used by both Claude Code (MCP servers) and Cowork (connectors). Authentication via OAuth or API keys.
Hook
A shell command (or HTTP call, MCP tool, LLM prompt, or agent) that fires at a specific lifecycle event. Unlike LLM behavior, hooks are deterministic — they always run.
Subagent
A nested agent loop running in isolated context. Built-in: Explore (read-only, Haiku), Plan (analytical), General-purpose (full tools). Custom: defined in .claude/agents/.
Plugin
A package bundling skills, agents, hooks, and MCP configs into a single installable unit. Distributed via marketplaces (GitHub repos). Same format for Code and Cowork.
LSP Plugin
Language Server Protocol integration giving Claude real-time type errors and go-to-definition as it edits. Available for 11 languages. Highest-impact plugin category.
opusplan
Hybrid mode: Opus plans the approach (deep reasoning), Sonnet executes the edits (fast, cheap). Best cost-quality tradeoff for complex refactoring.
Auto Mode
claude --auto. AI classifier approves routine actions (reads, grep) automatically while prompting for high-risk actions (writes, shell commands). The smart middle ground.
Dispatch
Cowork feature. Text a task from your phone → Cowork runs the workflow on your desktop → you return to finished files. Requires desktop app running.
Routines
Cloud-hosted Cowork automation that runs even when your laptop is closed. Distinct from desktop-bound Scheduled Tasks. Research preview.
Computer Use
Cowork's screen control. Claude can open apps, navigate browsers, run tools. Uses connectors first, browser second, screen control as last resort.
/btw
Side question at zero context cost. Uses the parent prompt cache. Never enters conversation history. Primary defense against context rot for meta-questions.
Worktree
claude -w <branch>. Isolated git worktree with its own directory and branch. Parallel Claude sessions without stashing or conflicts.
Headless Mode
claude -p "prompt". One-shot execution, no interactive session. For CI/CD, cron jobs, scripting. Use with --max-budget-usd for cost safety.

Frequently Asked Questions

How much does Claude Code cost?

Claude Code is included with paid Claude plans (Pro $20/mo, Max $100–200/mo, Team $30/user/mo, Enterprise custom). API-key users pay per-token. Typical session: $0.10–$2.25 depending on model and length. Use /cost to check and --max-budget-usd to cap.

Does it work offline?

The default setup requires an internet connection to reach Anthropic's API. Your code stays local — only prompts, tool calls, and file contents referenced in conversation are sent. Enterprise users running Claude via AWS Bedrock, Google Vertex AI, or Microsoft Azure Foundry keep traffic inside their VPC. Local model inference (fully air-gapped) is not currently supported.

Can I use my company's API key?

Yes. Set ANTHROPIC_API_KEY as an environment variable. Also supports AWS Bedrock (CLAUDE_CODE_USE_BEDROCK), Google Vertex (CLAUDE_CODE_USE_VERTEX), and Microsoft Foundry (CLAUDE_CODE_USE_FOUNDRY).

Is my code sent to Anthropic?

Only the portions Claude needs to see — files it reads, commands it runs, diffs it reviews. Code is not used for training. Enterprise plans offer additional data governance controls. Use .claudeignore to exclude sensitive files.

Claude Code vs. Cursor vs. GitHub Copilot?

Copilot is autocomplete (Generation 1). Cursor is chat + edit with context (Generation 2.5). Claude Code is fully agentic (Generation 3) — it reads, plans, acts, verifies, and iterates autonomously. Different tools for different workflows; many developers use Claude Code for complex tasks and Cursor/Copilot for quick inline completions.

What's the difference between CLAUDE.md and .claude/rules/?

CLAUDE.md is a single project policy file at your repo root. .claude/rules/*.md are modular rule fragments that can be path-scoped. Use CLAUDE.md for rules under 200 lines; split into rules/ when the project is large or rules vary by directory.

Do I need Cowork if I have Claude Code?

They serve different audiences. Code is for developers working in codebases. Cowork is for knowledge workers (marketing, legal, finance, ops) working with documents, spreadsheets, and connected tools. Same architecture — learn one, understand both.

Can I use Claude Code for non-code tasks?

Yes. Claude Code reads and writes any text file — Markdown, JSON, YAML, CSV. Many people use it for documentation, data analysis, and content generation. However, Cowork is specifically designed for non-code work and provides a better UX for those use cases.
